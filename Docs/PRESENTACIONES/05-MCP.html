TEMA 1

JSON Mode: Respuestas Tipadas

Los LLMs son inherentemente no deterministas. Para integrarlos en aplicaciones enterprise, necesitamos garantizar que la salida sea un JSON válido y estructurado que C# pueda deserializar de forma segura.

Parámetro format: "json"

Ollama y otros servidores locales fuerzan al modelo a generar exclusivamente JSON válido, eliminando texto explicativo.

🛡️ Records Inmutables en C#

Usamos public record con JsonPropertyName para mapear la respuesta a tipos fuertes.

System.Text.Json

Deserialización rápida y nativa. Sin dependencias de terceros como Newtonsoft.Json.

Models.cs - Definición de tipos 
public record WeatherResponse(
    [JsonPropertyName("city")] string City,
    [JsonPropertyName("temperature_c")] int Temperature,
    [JsonPropertyName("condition")] string Condition,
    [JsonPropertyName("humidity")] int Humidity);
Payload enviado a Ollama 
{
  "model": "llama3.2",
  "messages": [{
    "role": "user",
    "content": "Clima en Madrid hoy"
  }],
  "format": "json",  // ¡Clave para forzar JSON!
  "stream": false
}
TEMA 2

Orquestación con Minimal API

Construye un endpoint .NET que reciba una pregunta del cliente, recupere contexto vía RAG, consulte al LLM local y devuelva una respuesta estructurada en un solo flujo.

1

Recepción

El endpoint recibe la consulta del usuario y valida el modelo de entrada con DataAnnotations.

2

Recuperación

Se invoca el servicio RAG para obtener los chunks relevantes de la base de datos vectorial.

3

Generación

Se construye el prompt con contexto y se envía al LLM local en modo JSON.

Program.cs - Endpoint Minimal API 
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddSingleton<IRagService, RagService>();
builder.Services.AddHttpClient<ILocalAiClient, OllamaClient>();

var app = builder.Build();

// Endpoint principal de consulta RAG
app.MapPost("/api/rag-query", async (QueryRequest req, IRagService rag) =>
{
    // 1. Recuperar contexto relevante
    var context = await rag.RetrieveContextAsync(req.Question);
    
    // 2. Generar respuesta estructurada
    var answer = await rag.GenerateStructuredAnswerAsync(
        req.Question, context);

    // 3. Retornar JSON tipado al cliente
    return Results.Ok(answer);
});

app.Run();
TEMA 3

Model Context Protocol (MCP)

MCP es un estándar abierto impulsado por Anthropic que estandariza la forma en que los LLMs se conectan con datos y herramientas locales. Es el "USB-C" de la inteligencia artificial.

🔌 Estandarización

Un solo protocolo para conectar cualquier LLM con cualquier fuente de datos o herramienta, sin integraciones ad-hoc.

🔒 Seguridad y Control

El usuario mantiene el control total. Los datos nunca salen del entorno local a menos que se configure explícitamente.

🏗️ Arquitectura Cliente-Servidor

El Host (tu app .NET) se conecta a Servidores MCP que exponen recursos y herramientas específicas.

TEMA 4

Tools en C#: JSON-RPC

Implementa la lógica para que el LLM invoque funciones de C# basándose en el contexto de la conversación, usando el estándar JSON-RPC sobre stdio o SSE.

El Flujo de una Tool Call

  1. 1 El cliente .NET envía el mensaje del usuario junto con la lista de tools disponibles (descripciones en JSON).
  2. 2 El LLM decide si necesita usar una herramienta y responde con un objeto tool_call en lugar de texto.
  3. 3 La aplicación .NET ejecuta la función de C# correspondiente con los argumentos proporcionados.
  4. 4 El resultado se envía de vuelta al LLM como un mensaje de tipo tool para que genere la respuesta final.

Implementación en C# Puro

  • ✓ Definir herramientas como métodos con atributos personalizados ([McpTool]).
  • ✓ Serializar la lista de herramientas al formato esperado por el LLM (OpenAI function calling format).
  • ✓ Usar un switch o diccionario de delegados para enrutar la llamada al método correcto.
  • ✓ Manejar errores de ejecución de herramientas y devolver mensajes de error estructurados al LLM.

Ejemplo: Definición y Ejecución de Tools

ToolService.cs - Registro y ejecución 
// 1. Definir la herramienta
public class WeatherTool
{
    [McpTool("get_weather", "Obtiene el clima actual de una ciudad")]
    public WeatherData Execute(string city)
    {
        // Lógica de negocio real en C#
        return new WeatherData(city, 22, "Soleado");
    }
}

// 2. Procesar la decisión del LLM
public async Task<string> ProcessToolCallAsync(ToolCall call)
{
    switch (call.Name)
    {
        case "get_weather":
            var args = JsonSerializer.Deserialize<WeatherArgs>(call.Arguments);
            var result = new WeatherTool().Execute(args.City);
            return JsonSerializer.Serialize(result);
            
        default:
            throw new InvalidOperationException($"Tool desconocida: {call.Name}");
    }
}

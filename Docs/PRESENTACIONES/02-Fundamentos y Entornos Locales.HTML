TEMA 1

IA Open Source: El Ecosistema

Entender la diferencia entre modelos propietarios y open source es el primer paso para tomar el control de tu infraestructura de IA.

Modelos Propietarios

  • • API externa (OpenAI, Anthropic, Google)
  • • Datos enviados a servidores de terceros
  • • Costos recurrentes por token
  • • Sin control sobre el modelo base
  • • Vendor lock-in

Modelos Open Source

  • • Ejecución 100% local (privacidad total)
  • • Pesos del modelo disponibles públicamente
  • • Fine-tuning y cuantización personalizados
  • • Sin costos recurrentes de API
  • • Comunidad activa (Hugging Face, GitHub)

Hugging Face: El GitHub de la IA

Plataforma central del ecosistema. Repositorio de modelos, datasets y espacios de demostración.

TEMA 2

Cuantización: Hacer viable la IA local

Reducir la precisión de los pesos del modelo para que quepa en hardware consumidor, manteniendo la mayor parte de su capacidad.

¿Qué es la Cuantización?

Es el proceso de reducir la precisión numérica de los pesos del modelo (de float32 a int4), reduciendo drásticamente el consumo de memoria RAM/VRAM con una pérdida mínima de calidad.

Regla de Oro
1B de parámetros ≈ 0.7 - 1 GB de RAM en formato GGUF Q4_K_M

Formato GGUF

GGUF (GPT-Generated Unified Format) es el formato estándar creado por el equipo de llama.cpp. Permite cargar modelos cuantizados de forma eficiente en CPU y GPU.

  • ✓ Metadatos embebidos (tokenizer, chat template)
  • ✓ Memory-mapped para carga rápida
  • ✓ Compatible con Ollama, LM Studio, llama.cpp

Comparativa de Niveles de Cuantización

Formato Bits por peso Tamaño (7B) Calidad Uso recomendado
Q2_K ~2.5 ~2.8 GB Baja Hardware muy limitado
Q4_K_M ~4.5 ~4.4 GB Buena ⭐ Sweet spot (recomendado)
Q5_K_M ~5.5 ~5.2 GB Muy buena GPU con 8GB VRAM
Q8_0 ~8.5 ~7.8 GB Excelente Casi indistinguible del original
F16 16 ~14 GB Original Fine-tuning, investigación

TEMA 3

Destilación: Lo grande se hace pequeño

La destilación permite que modelos pequeños "aprendan" de modelos gigantes, heredando sus capacidades de razonamiento pero ejecutándose en hardware modesto.

Microsoft Phi-3 / Phi-3.5 (3.8B)

Entrenado con datos sintéticos de alta calidad. Razonamiento comparable a modelos 25x más grandes.

Meta Llama-3-8B

El estándar de facto para despliegue local. Excelente balance entre capacidad y recursos.

Alibaba Qwen2.5 (3B / 7B)

Multilingüe nativo, excelente en código y matemáticas. Muy competitivo en benchmarks.

TEMA 4

Despliegue de Servidores Locales

Configura tu infraestructura de inferencia local. Python solo se usa dentro de los binarios nativos, nunca en tu código de aplicación .NET.

Ollama

RECOMENDADO
http://localhost:11434

Motor basado en llama.cpp. Gestión de modelos vía CLI. API REST nativa.

Terminal
# Instalar Ollama
$ curl -fsSL https://ollama.com/install.sh | sh
# Descargar modelo Llama 3.2 (3B)
$ ollama pull llama3.2
# Descargar modelo de embeddings
$ ollama pull nomic-embed-text
# Listar modelos instalados
$ ollama list
# Probar chat interactivo
$ ollama run llama3.2

LM Studio

GUI FRIENDLY
http://localhost:1234/v1

Interfaz gráfica para gestión visual. Compatible con API de OpenAI. Ideal para desarrollo rápido.

API Request (cURL)
# Endpoint compatible OpenAI
$ curl http://localhost:1234/v1/chat/completions \
-H "Content-Type: application/json" \
-d '{
"model": "llama-3.2-3b",
"messages": [{
"role": "user",
"content": "Hola"
}]
}'

Referencia Rápida de Endpoints

Ollama API

  • POST /api/generate Generación cruda
  • POST /api/chat Chat con mensajes
  • POST /api/embeddings Vectorización
  • GET /api/tags Listar modelos

LM Studio (OpenAI Compat)

  • POST /v1/chat/completions Chat
  • POST /v1/completions Completado
  • POST /v1/embeddings Embeddings
  • GET /v1/models Listar modelos
